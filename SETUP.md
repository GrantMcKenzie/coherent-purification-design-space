# Setting this up on your machine

Plain-language walkthrough. Every command goes in Terminal.

## 0. Seeing the hidden folder

This project contains a folder called `.github`. Names beginning with a dot are
hidden by macOS. In Finder, press **Cmd + Shift + .** to show them (the same
shortcut hides them again). Git tracks these files normally whether or not
Finder shows them.

## 1. Go to the project folder

```bash
cd ~/Desktop/coherent-purification-design-space
ls
```

You should see `README.md`, `verify_all.py`, `finite_rank_purification`, and so on.

## 2. Set up an isolated environment

This keeps the project's packages separate from everything else on your Mac.

```bash
conda deactivate                     # if (base) shows in your prompt
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-frozen.txt
```

Each new Terminal window needs `source .venv/bin/activate` again.

## 3. Check that it runs

```bash
python -m pytest tests/ -q           # ~8 seconds, expect "22 passed"
python verify_all.py                 # ~15 minutes, expect "All 91 checks passed."
```

If either fails, stop and investigate before going further.

## 4. Fill in the placeholders

In `README.md` and `CITATION.cff`, replace every `GrantMcKenzie/coherent-purification-design-space` with your GitHub
username and the repository name. Leave the `XX.XXXX/zenodo.XXXXXXX` DOI
placeholders alone -- Zenodo issues those later (step 7).

## 5. Create the repository

On github.com: **New repository**, name it `coherent-purification-design-space`,
set it **Private**, and do **not** tick "Add a README" or "Add a license" --
this project already has both, and letting GitHub add its own creates a conflict.

## 6. Push

```bash
git init
git add .
git commit -m "Verification package for the purification design-space paper

91 assertions and 22 unit tests; two independent engines cross-validated.
Verified on Python 3.11 (arm64) and 3.12 (x86_64)."
git branch -M main
git remote add origin https://github.com/GrantMcKenzie/coherent-purification-design-space.git
git push -u origin main
```

When it asks for a password, GitHub will not accept your account password. Create
a **personal access token** instead: github.com -> Settings -> Developer settings
-> Personal access tokens -> Fine-grained tokens -> Generate new token, give it
read/write access to this repository, then paste the token as the password.

Then open the repository's **Actions** tab. The workflow runs by itself and takes
roughly twenty minutes per Python version. A green check means an independent
machine reproduced every number in the paper.

## 7. Later: the DOI

Only once you are ready to make the repository public, at arXiv posting.

1. Sign in to zenodo.org with GitHub, open the GitHub tab, toggle this
   repository **on**. Do this *before* creating the release -- Zenodo only sees
   releases made after the toggle.
2. On GitHub: **Releases -> Draft a new release**, tag `v1.0.0`.
3. Zenodo issues two DOIs. Cite the **version** DOI in the paper (a referee needs
   the exact code you ran); put the concept DOI in the README.
4. Paste the DOIs into `README.md` and `CITATION.cff`, and into the paper's
   Data and code availability section.

## Note on figures

`.gitignore` excludes `figures/*.pdf`, so plots are not committed. They are
regenerated by `make_figures.py` and CI uploads them as downloadable artifacts,
which keeps the repository small and stops the figures drifting out of step with
the code. If you would rather see them in the repository, delete the
`figures/*.pdf` line from `.gitignore` before your first commit.
